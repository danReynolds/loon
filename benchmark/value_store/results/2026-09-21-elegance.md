# Simplification screen — September 21, 2026

[Frozen sources, raw samples and command receipts](2026-09-21-elegance.json)

## Decisions

Keep three cleanups. Keep the existing ValueStore pruning implementation after
two simpler alternatives showed undesirable costs. The baseline is the incoming
working tree, including the shared typed getter, rather than `main` or HEAD.
Each candidate was measured independently by overlaying its one production file
on that baseline. Earlier uncommitted getter changes remain intact.

### Reference counts: keep

`ValueRefStore` now uses one `_subtractRef` helper in writes and deletes, updates
increments with `(refs[value] ?? 0) + 1`, and checks for an empty reference map
once after the deletion loop. A write adds its new value before subtracting the
previous unequal value, so that path cannot empty the reference map. Removing
that unreachable cleanup also removes nested branches.

AOT milliseconds, batches of 20k operations on eight-segment paths with 64
shared values; subtree deletion is one operation:

| Operation | Before | Shared counting | Change |
| --- | ---: | ---: | ---: |
| Write | 14.329 | 12.507 | 13% less time |
| Overwrite | 18.609 | 15.629 | 16% less time |
| Delete leaves | 21.761 | 19.317 | 11% less time |
| Delete subtree | 0.025 | 0.018 | 28% less time; only 7 microseconds |

This is a useful simplification with fewer map lookups, not just fewer lines.

### Dependency updates: keep

Replace three repeated cases with two loops: add new memberships, then remove
departed memberships. Finish with one decision to write or delete the entry.
No intermediate difference sets are allocated. The defensive copy of the
builder's result stays in place, as do existing null/empty semantics: an initial
empty set gets an entry, while clearing a nonempty entry removes it.

The fixture graph has 20k documents; sparse batches update 200 documents.

| AOT operation | Before, ms | Unified loops, ms |
| --- | ---: | ---: |
| Initial setup, one dependency each | 14.582 | 14.865 |
| Initial setup, eight dependencies each | 39.590 | 38.388 |
| Replace sole dependency, 200 documents | 0.115 | 0.112 |
| Replace one of eight, 200 documents | 0.248 | 0.240 |
| Unchanged set of eight, 200 documents | 0.083 | 0.081 |
| Clear sole dependency with null, 200 documents | 0.083 | 0.088 |

Comparable overall, not a universal speedup. The null-clear case is about 6%
slower here, or 5 microseconds per 200-document batch. Some larger apparent
improvements also appeared in unchanged controls; do not attribute them to the
refactor. The code reuse is worthwhile without claiming a throughput gain.

### Propagation collection-map helper: keep

`_CollectionValues<T>` encapsulates the last path/map pair and invalidation.
The synchronous walk creates one helper for events and one for the reverse
dependency index. The recursive traversal no longer maintains both pairs of
mutable locals or repeats their lookup logic. State expires with that walk;
there is no persistent cache, event-tick cache, or deletion lifecycle to manage.

If an event write creates a map, invalidate the helper and resolve on the next
read. The old implementation immediately refreshed that map even if the next
document belonged to a different collection. Unusual parent/id boundaries still
use full-path access. Cycle detection and existing mutative events are preserved.

| AOT propagation of 20k dependents | Before, ms | Helper, ms |
| --- | ---: | ---: |
| One collection, empty event store | 2.715 | 2.726 |
| One collection, existing event map | 2.630 | 2.675 |
| 5,000 collections, empty event store | 13.129 | 11.252 |
| 5,000 collections, existing event maps | 10.522 | 10.527 |

Mostly comparable, with about 14% less time for scattered cold maps. Fixtures
include cached observer values, a diamond/cycle and validation that the source's
modified event survives propagation.

### Eager pruning: reject

Always removing an empty child and checking `node.isEmpty` is attractive:

```dart
if (_delete(child, path, nextStart, recursive)) {
  node.remove(segment);
}
return node.isEmpty;
```

But it adds emptiness checks on ancestors whose child survives. Deep deletion
measured 6.027 → 6.486 ms, about 8% more time. Restoring the early return avoids
those checks, but still mutates every empty ancestor rather than skipping maps
that will be discarded with their parent. On 20k small subtrees that version
measured 4.806 → 6.831 ms, about 42% more time. Its two process medians were
6.508/7.288 ms versus 4.739/4.873 ms for the baseline. Deep-path results in this
follow-up were noisy and do not establish a speedup.

The original branch avoids real work on this shape. Both alternatives were
removed; `ValueStore` pruning is unchanged from the incoming working tree.

## Method and validation

All benchmarks are Dart and run headlessly. Each source variant was frozen and
compiled before measurements. Setup and checks are outside timed intervals;
checks remain active in AOT. Two fresh processes per variant reverse execution
order on the second pass; each uses three warmups and at least 80 ms of warmup
phase time. Store repeats use nine recorded trials; manager screens use seven.
Numbers are pooled medians, not confidence intervals.

The first JIT/AOT store screen encountered one-minute host load around 18–44,
with enormous variation even in unchanged operations. It is archived but not
used for the decisions. A focused AOT repeat under lower load gave the store
numbers above. No reliable JIT performance conclusion is drawn from that first
screen. The store repeat took 16.3 seconds including compilation/process time;
the pruning follow-up took 6.3 seconds and the manager screen 27.5 seconds.

The new optional `run_core.dart --suite manager_core` screen compiles the actual
manager/store method bodies with explicit benchmark document/observer fixtures.
Their path, hash and equality match the relevant production behavior; the
fixture omits document data storage, persistence and observer delivery. It
isolates manager algorithms, not complete Flutter-engine or mobile performance.
Fixture and workload source text is archived alongside production snapshots.

Validation against the real Loon library:

- 28 store tests passed, including randomized model checks and unusual paths.
- 20 focused dependency tests passed, including propagation, cycles, deletion,
  mutable builder sets and the new null/empty/child-preservation regression.
- Final store/traversal rerun: 31 passed (overlaps the counts above; 48 distinct
  focused tests in total). Analysis of the affected code and benchmarks is clean.
- Full PR correctness/performance qualification remains deferred until the PR
  settles, as agreed. These are local, uncommitted iteration changes.
