# Callback versus lazy iterable, 2026-09-15

Local macOS arm64, Dart 3.12.2, Flutter test/JIT. Each implementation ran in two independent processes with reversed method order, five warmups and fifteen measured trials per process. Setup and correctness checks are outside timed intervals. The table uses pooled medians of 30 samples; order effects are visible in individual pass medians.

## Final draft: delegate existing bucket iteration

`iterable_draft.dart` uses `yield* values.values.cast<T>()`, then recursive `yield*` for child nodes. The callback has the same traversal order and result semantics. Neither constructs an intermediate result collection. Export and union intentionally create their final output collections.

Cleanup uses actual Document handles, retained entry objects, a forward ValueStore and reverse ValueStore of sets. It removes 100k documents sharing one source and verifies that an unrelated surviving dependent remains. This is an isolated model of DependencyManager cleanup, not full Loon deletion/notification. Union flattens 10k reverse-index sets containing 200k memberships into 100k distinct documents.

## Initial version: yield each value

The first implementation used `for (final value in values.values) yield value as T;`. Its 100k sum medians were 4.557/4.843 ms, versus callback 0.969/0.896 ms. Cleanup was 27.636/27.521 ms versus 22.845/21.887 ms. Delegating each values bucket closed most of this gap without a custom Iterator. These were separate process pairs, so compare each iterable with its callback control.

The final 100k sum pass medians were callback 0.964/0.978 ms and iterable 0.959/1.125 ms; cleanup was callback 22.261/24.746 ms and iterable 23.330/25.609 ms. Both union and the tiny 1k workloads showed order/host/JIT variation; do not claim a reliable winner from small pooled differences. Export also varied in the initial run. These measurements do not identify allocations or prove release/device performance.

## API recommendation

Prefer a single lazy `valuesUnder(path)` API using bucket delegation. It gives callers for-in, break/continue/return, map/where/take, and explicit toList/toSet when needed. A separate callback API is not justified by these current measurements. A custom Iterable/Iterator remains possible later without changing the caller contract.

The view is live: traversal starts when consumed, repeats on each new iteration, and must complete before deleting the traversed subtree. Structural mutation of the traversed store during iteration is unsupported. Modifying the separate reverse index during forward traversal is safe. Nulls, duplicate values, own value plus descendants, root and missing paths have matching semantics.

Both tests passed in all four processes. The final draft has no analyzer issues. Production library files were not changed for this experiment.
