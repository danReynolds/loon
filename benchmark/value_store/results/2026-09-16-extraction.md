# Extraction costs and Dart-only tooling — September 16, 2026

The earlier extraction-versus-traversal gap reproduces in release AOT. For large
value buckets, almost all extraction time is still present when the tree is
removed and a prebuilt list is converted to a set. Improving tree navigation helps
node-heavy shapes, but does not remove the cost of producing a distinct snapshot.

The public API can remain unchanged for now. Keep `extractValues` for consumers
that need its set semantics. If dependency cleanup's set construction becomes
worth eliminating, a private value visitor can serve that internal caller without
committing to a public traversal API. No production extraction/traversal change
was made in this experiment.

[Raw measurements and receipts](2026-09-16-extraction.json) accompany this report.

All workloads, the native runner, source transforms, report generation and log
decoding are now Dart. Python scripts and their generated bytecode were removed.

The first four fixtures have large buckets (or one flat bucket); their time is
largely accounted for by set construction. The last two have many small maps,
where reducing traversal overhead helps substantially. Smaller differences in the
large-bucket cases should not be treated as established improvements.

## The localized extraction improvement

The draft replaces key iteration plus a second map lookup with `Map.forEach`,
and returns immediately after consuming a leaf's value bucket:

```dart
final Map<String, T>? localValues = node[_values];
if (localValues != null) {
  result.addAll(localValues.values);
  if (node.length == 1) return;
}
node.forEach((key, child) {
  if (key != _values) collect(child, result);
});
```

[extraction_draft.dart](../extraction_draft.dart) contains the executable proposal.
It preserves fresh mutable snapshots, value equality, first-seen order, nulls,
and inclusion of the selected path's own value. It is a benchmark helper using
`inspect()`, not an adopted production implementation. The direct per-value
`Set.add` loop is also measured; neither alternative avoids hashing or deduplication.

Switching to unordered `HashSet` is not a general improvement: unique integers
cost 8.843 ms and identity entries cost
15.709 ms here, while also
changing iteration order.

## Could a cached set replace traversal?

Copying an already-built set takes 0.575
ms for 100k unique integers and 0.630
ms for 100k identity entries in this run. This is a read-side control only: it
excludes creating, maintaining and retaining that cache. Small cached-set copies
approach the timer's resolution and are not meaningful timing estimates.

Such a cache helps repeated reads without intervening mutations. In dependency
cleanup, we extract the subtree and immediately delete it, so caching a previous
result is generally unhelpful. Maintaining distinct values incrementally at each
ancestor instead moves work and memory to writes/deletes and needs reference
counts for duplicates—the role of the existing ValueRefStore. No such cache was
introduced or claimed as a measured overall win.

A set-returning API also differs semantically from traversal: for values
`[7, 7, 9]`, extraction produces `{7, 9}`, while traversal yields all three
occurrences. Returning a list or a live iterator would change the current API's
uniqueness/snapshot behavior, not merely optimize its implementation.

## Method, checks and limits

- Flutter 3.44.4 / Dart 3.12.2; native macOS arm64. JIT debug and release AOT are
  separate series; no compiler-mode inference from one to the other.
- Three suites × two modes × four fresh-process passes = **24 timing processes**.
  Each operation has **60 samples**: 15 per process after at least eight warmups
  and 500 ms of warmup phase time. Setup/checks count toward the warmup time floor.
- Job and comparison-method order reverse on alternate passes. All builds and
  135 core/benchmark/demo checks completed before timing. Release-mode membership
  and result checks remain enabled. This is steady-state data; object hashes in
  the isolated extraction fixtures have already been exercised before timing.
- Nullable/equal values, independent snapshots and random write/delete sequences
  were checked for the ordered extraction proposals. Duplicate-value sums use
  separate expected results for occurrence traversal and distinct-set extraction.
- Dart tooling reproduced all prior native report medians and baseline/combined
  variant source hashes. It rejected incomplete matrices, truncated/duplicate log
  frames, wrong compilation modes and failed benchmark output.
- Analyzer passed. All measured Dart source hashes match the final workspace.
  Raw samples, individual process medians, source/build hashes and command
  receipts are archived. Process-median ranges are not confidence intervals.
- Other host activity was present; no claim of a fully idle lab, mobile-device
  performance, heap retention or allocation-byte measurements. The case for the
  large gap is stronger than any small percentage differences between candidates.
